# Ember is #FF6A00

Date: 2026-09-08. Status: settled by Shreyash, 2026-09-08. Closes open decision 1 in
`docs/design/frontend-design.md`.

**Chosen:** the accent is **Ember `#FF6A00`**, and Ember-as-text on a light ground is
**Ember-Deep `#A84A00`**. Both values are written into `ui/src/brand/tokens.css` *and*
`ui/offgrid.preset.cjs`, so docket is internally consistent even where the handoff is not.

**Over:** `#E8743C` / `#B8531F`, which is what the UI has rendered since it was built.

**Why.** The brand handoff contradicts itself on this value, and did so in v1.2 and again
in v3.0. Four sources say `#FF6A00`: `tokens/tokens.css`, the `value` field in
`tokens/tokens.json`, the semantic token table in the handoff `README.md`, and both theme
maps in `tokens.json`. Two say `#E8743C`: `tokens/tailwind.preset.js` and
`tokens/tokens.scss`. `tokens.json` additionally contradicts itself — its `ember` entry
carries `"value": "#FF6A00"` beside `"rgb": [232, 116, 60]`, which is `#E8743C`.

The build previously took `#E8743C` because in v1.2 the README agreed with the preset. In
v3.0 the README agrees with `tokens.css`, so the majority moved. `tokens.json` names
itself "source of truth" in the header of `tokens.css`, and its `value` field is the field
that means the colour; `rgb` is a derived convenience field and is the more likely place
for a stale number to survive.

This is not a claim that the handoff is right — it is a claim about which reading is best
supported, made so the build can proceed. The conflict is real and unresolved upstream.

**Would reverse if:** the brand owner rules for `#E8743C`, which is one edit to two files
plus regenerated figures — cheap, provided it happens before the proposal figures are
final. Flag it to them; do not wait on it.
